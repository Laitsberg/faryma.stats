# Выпуск

Порядок, которым сюда попадает всё. Пропускать шаги нельзя: сайт собирается
из `main` сразу, промежуточной площадки нет, и сломанное увидят зрители.

## 1. Проверки

    npm test

97 проверок, около шести минут. Ждать до конца. `--test-concurrency=1`
в команде не случаен: три браузера разом роняют раннер.

Красное — разбираться, а не коммитить. Если проверка упала по своей вине,
а не по вине кода, чинить проверку в том же коммите и говорить об этом
вслух, а не молча.

## 2. Экраны

    npm run shots

Поднимает сайт локально, открывает в трёх ширинах (1440, 940, 390),
складывает картинки во временную папку и проверяет два условия:

* страница не едет вбок ни на одной ширине;
* колонки первого экрана одной высоты на широком экране.

Скрипт выходит с ошибкой, если что-то не сошлось. Путь к картинкам он
печатает последней строкой; можно задать свой: `npm run shots -- /tmp/шоты`.

## 3. Посмотреть

**Открыть картинки и посмотреть на них.** Это не формальность: проверки
ловят «сломано», но не ловят «некрасиво» и не ловят «пусто». Обе последние
беды приходили именно так — сначала пустовало под карточкой эфира, потом
под шкалой, и оба раза находил это владелец, а не проверки.

На что смотреть:

* нет ли пустоты рядом с короткой колонкой;
* не обрывается ли список посреди строки без подсказки, что он длиннее;
* читаются ли подписи на графиках поверх нового фона;
* на телефоне — не слиплось ли, не уехал ли текст за край.

## 4. Коммит

Сообщение по-русски, первой строкой — что изменилось для читателя сайта,
а не что изменилось в файлах. Дальше пустая строка и подробности: почему
так, что при этом сломалось и как чинилось. Если по дороге ловилась грабля,
описать её — в следующий раз на неё наступит тот, кто не читал переписки.

    git add -A
    git commit

## 5. В ветку и в main

    git push -u origin claude/faryma-stats-dashboard-fsijqq
    git fetch origin main
    git checkout main
    git merge --ff-only claude/faryma-stats-dashboard-fsijqq
    git push origin main
    git checkout claude/faryma-stats-dashboard-fsijqq

**Если пуш в main отбило** — почти наверняка воркфлоу обновления архива
успел закоммитить свежие данные. Это норма, он ходит четыре раза в сутки.
Не форсить:

    git fetch origin main
    git checkout main
    git rebase origin/main
    npm test          # данные другие — проверить на них заново
    git push origin main
    git checkout claude/faryma-stats-dashboard-fsijqq
    git rebase main
    git push -f origin claude/faryma-stats-dashboard-fsijqq

Форс тут только на своей ветке и только после ребейза на `main` —
в `main` не форсить никогда.

## 6. Сказать, что сделано

Своими словами и без хвастовства: что изменилось, что при этом
сломалось и как чинилось, чего не сделано и почему. Если проверка падала
или что-то осталось незакрытым — сказать прямо, а не обойти.
