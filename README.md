# Статистика разносов — «композитор разносит»

Дашборд по архиву стрима, где композитор разбирает присланные зрителями
треки. Считает всё в браузере, бэкенда нет.

Открыть: **https://farymastats.info**

Домен куплен до 24.08.2027, автопродление выключено. Когда он отпустится,
надо убрать его в Settings → Pages и удалить файл `CNAME` из репозитория —
иначе старый адрес `laitsberg.github.io/faryma.stats/` продолжит
перекидывать на уже чужой домен, и сайт станет недоступен по обоим адресам.

## Что где лежит

    index.html          разметка страницы, подключение скриптов
    css/style.css       все стили
    js/config.js        ← ССЫЛКА НА ТАБЛИЦУ и настройки: шкала, цвета, отсечки
    js/parse.js         разбор строк таблицы: оценки, артисты, ссылки, тайм-коды
    js/ui.js            общее: таблицы, графики, сортировка
    js/sections.js      по функции на каждый раздел страницы
    js/game.js          «угадай оценку» — только треки с ютуба, с плеером
    js/profile.js       карточки по клику: исполнитель, заказчик, вселенная, стрим
                        (#artist=…, #user=…, #source=…, #stream=…)
    js/app.js           загрузка данных и сборка
    icons/              значок вкладки: svg плюс png для старых браузеров и iOS
    site.webmanifest    имя и иконки, если сайт вынесут на домашний экран
    vendor/             PapaParse и Chart.js
    data.csv            выгрузка архива, обновляет воркфлоу
    data/countries.json страны исполнителей из MusicBrainz

Правки чаще всего нужны в `js/config.js` (пороги, цвета) и `js/sections.js`
(что показывает конкретный раздел).

## Запустить локально

Нужен локальный сервер — напрямую из файла браузер не даст прочитать CSV:

    python3 -m http.server 8000

Дальше http://localhost:8000

## Откуда берутся данные

По умолчанию страница читает `data.csv` из этого же репозитория. Его раз в
сутки обновляет воркфлоу из `.github/workflows`: скачивает таблицу, дописывает
страны и коммитит. Так копится история по датам, которой в самой таблице нет.

Браузер при этом к Google не ходит вообще — файл лежит на том же домене.
Страница грузится быстрее и работает, даже если Google недоступен.

Если понадобится тянуть таблицу напрямую, впиши адрес CSV-выгрузки в
`SHEET_CSV_URL` в начале `js/config.js`. Учти: для этого лист должен быть
именно **опубликован** (Файл → Поделиться → Опубликовать в интернете → CSV),
обычная ссылка на документ упрётся в запрет браузера на чужой домен.

## Какие колонки нужны

Читаются по названиям заголовков, порядок не важен, лишние игнорируются.

| Колонка  | Для чего                                                 |
|----------|----------------------------------------------------------|
| `Что`    | «Артист — Трек {альт} [источник]»                         |
| `Оценка` | шкала, распознаётся 99,6% значений                        |
| `Где`    | ссылка на трек: раздел про площадки и клик в поиске       |
| `Кто`    | лидерборд заказчиков                                      |
| `Тип`    | донат / долг / заказ / очередь                            |
| `Откуда` | аниме / игра / фильм                                      |
| `Жанр`   | жанровая аналитика, несколько значений через `/`          |
| `Тэги`   | progressive / cover / meme / live, через `,` или `/`      |
| `Когда`  | тайм-код внутри стрима, `MM:SS` или `H:MM:SS`             |

Даты берутся из строк-разделителей вида `СТРИМ №271 (22.08.26)`, а ссылка
на запись стрима — из колонки `Где` этой же строки. Каждый трек наследует
дату и запись своего стрима, поэтому в поиске номер стрима ведёт прямо на
минуту разноса: `?t=1h23m45s`. Формат ссылки и разбор тайм-кода взяты из
бота [FarymaSearch](https://github.com/Laitsberg/FarymaSearch), чтобы сайт
и бот вели себя одинаково.

Плюс строки-разделители вида `СТРИМ №271 (22.08.26)` в колонке `Что` —
из них берутся даты. У самих треков дат нет, но каждый лежит под своим
стримом и наследует его дату. Разделителей 272, номера идут подряд без
пропусков, все даты читаются.

**Архив отсортирован от новых к старым**: первая строка файла — последний
стрим. Поэтому сортировать по порядку строк нельзя, надо по дате.

## Как считается оценка

Шкала переводится в баллы 0–10: гениально 10, атлична 8, хорошечно 6,
нормас 4, ну такое 2, кринж-контент 0. Модификатор `+` даёт +0,3, `++` +0,6,
`-` −0,3, `- -` −0,6. Комментарии в скобках отбрасываются, пробелы внутри
модификаторов не важны — «атлична +» и «атлична+» одно и то же.

Крайние ступени односторонние: «гениально» — потолок, плюса к нему не
существует; «кринж-контент» — дно, минуса к нему тоже нет. Зато
«кринж-контент+» и «кринж-контент++» вполне встречаются и означают «не
такой уж кринж». Модификатор всегда двигает оценку внутрь шкалы, поэтому
существующих ступеней 26, а не 30.

Из 6701 строки с оценкой распознаётся 6673. Оставшиеся 28 — разовые шутки
(«ГЕ-НЯ-АЛЬНО», «БДСМ ШЕДЕВР»), которые к шкале не сводятся.

Написание имён склеивается: «HOYO-MiX» и «HOYO-MIX» — один исполнитель,
«@Sadierre» и «Sadierre» — один заказчик. Показывается тот вариант, который
в архиве встречается чаще.

## Обновление архива

Воркфлоу `.github/workflows/update.yml` раз в сутки скачивает таблицу,
дописывает страны и коммитит результат. Запустить руками — вкладка
**Actions** → «Обновить архив» → **Run workflow**.

Три шага, каждый — отдельный скрипт, их можно гонять и по отдельности:

    node scripts/fetch-sheet.mjs    скачать таблицу в data.csv
    node scripts/snapshot.mjs       записать снимок дня в history.jsonl
    node scripts/countries.mjs      докачать страны из MusicBrainz

`fetch-sheet.mjs` проверяет скачанное перед записью: Гугл на закрытый
доступ отвечает не ошибкой, а страницей входа, и без проверки она молча
легла бы вместо архива. Также не даёт перезаписать архив выгрузкой,
которая резко короче предыдущей.

Какой лист качать, задаётся переменными `SHEET_ID` и `SHEET_GID`
в воркфлоу. Сейчас это вкладка «Уже разнесли (архив)», `gid=957661826`.

В октябре 2026 композитор завёл для архива новый лист: те же колонки,
что были, плюс несколько новых справа — «Три интересных факта»,
«О чём трек?» и оценки популярности. Прежний лист остался под именем
«Уже разнесли (архив до октября 2026)», `gid=1372192852`, и больше не
пополняется.

### Два файла с архивом

Выгрузка одна, а файла из неё получается два — у каждого свой читатель.

    data.csv        10 колонок, 1,7 МБ   — сайт статистики
    data/full.csv   22 колонки, 18,4 МБ  — каталог на сайте композитора

`data.csv` качает каждый, кто открыл farymastats.info, поэтому в нём
только то, что сайт читает: `Что`, `Где`, `Когда`, `Кто`, `Тип`,
`Оценка`, `Откуда`, `Тэги`, `Жанр`, `Фича`. Список живёт в `KEEP`
в `scripts/trim-csv.mjs` — понадобится новая колонка, её надо дописать
туда, иначе она до сайта не доедет. С полным набором колонок файл весил
бы 18,4 МБ: в «Трёх интересных фактах» и «О чём трек?» лежат длинные
тексты, и статистике они ни к чему.

`data/full.csv` — та же выгрузка целиком, как её отдал Гугл. Она нужна
каталогу на официальном сайте композитора: он читает её отсюда, и ходить
в саму таблицу ему не приходится. Оба файла пишутся из одной загрузки
и записываются только после того, как скачанное прошло все проверки, —
разойтись они не могут.

Репозиторий от этого почти не растёт. Первый коммит с полным файлом
добавил около 5,5 МБ, а дальше git хранит только разницу: проверено на
пяти подряд обновлениях — размер не изменился вовсе.

**Если архив переедет на новую вкладку.** Номер вкладки (`gid`) виден
в адресе: открой нужную вкладку в таблице и возьми число после `#gid=`.
Его надо вписать в `SHEET_GID` в `.github/workflows/update.yml`.

Переезд важно не проспать. Экспорт по номеру работает и для скрытых
вкладок, поэтому старый лист, спрятанный и замороженный, продолжит
скачиваться как ни в чём не бывало: колонки на месте, длина прежняя,
и сайт тихо замрёт на позавчерашнем дне. Сторож на этот случай один:
номер самого свежего стрима в выгрузке не может быть меньше того, что
уже лежит в `data.csv`. Он ловит подмену на старую копию, но не ловит
случай «читаем ту же копию, что и вчера» — тут поможет только глаз.

### История по датам

В таблице дат нет — только порядок строк. Поэтому `snapshot.mjs` каждый
день дописывает строку в `data/history.jsonl`: сколько разносов накопилось,
средний балл, сколько исполнителей. Разница между днями показывает, что
разобрали за это время, и через месяц-другой у архива появляется настоящая
ось времени.

### Страны исполнителей

`countries.mjs` спрашивает MusicBrainz — бесплатно, без ключа, но не чаще
одного запроса в секунду. Исполнителей около четырёх тысяч, поэтому первый
прогон идёт больше часа. Результат копится в `data/countries.json`, уже
известных скрипт не переспрашивает — прервалось, запустил снова, продолжит.

По расписанию за раз спрашивается 150 новых: за сутки их набегает немного.
Первый полный прогон делается руками через Run workflow с большим числом.

MusicBrainz возвращает уверенность совпадения. Ниже `COUNTRY_MIN_SCORE`
(по умолчанию 90) результат не берётся: лучше «не знаем», чем похожий по
названию, но не тот исполнитель. Пока страны не набраны, раздел на странице
скрыт — соседний раздел про письменность работает всегда.
